## Page model (`models/react/ScheduleEditorPage.js`)
`waitForLoad()`, `weekButtons()`, `selectWeek(abbr)`, `selectedWeek()`, `games()` → `[{ recordIndex, away, home, day, time, played }]` read from `data-*` and the control values, `setTeam(i, 'home' | 'away', abbr)` (`selectOption`), `setDay(i, abbr)`, `setTime(i, text)` (fill + Enter), `viewInTable(i)` (the button), `viewInTableByContextMenu(i)`, `errorAlert()`. ## Spec (`react/schedule.spec.js`)
Each test opens `sandbox.careerPath` with `launchWithDefaultOptions({ ui: "react" })`. Check saved data with `readSavedTable` / `readTableFromDisk` (SeasonGame) and seed preferences with `preferences`.
1. **Loads**: Schedule → 28 week buttons, P1 selected, at least one game. Selecting week 1 shows games whose teams are known abbreviations.
2. **Edits are saved** (auto-save on, the default): change the day, the time (`"8:20 PM"` → `TimeOfDay 1220`) and the away team of game 0 in week 1. Poll the file on disk until exactly those fields of that record have changed. The away team's reference decodes to the Team table row of the chosen team.
3. **Auto-save off** (`preferences: { general: { autoSave: [false] } }`): edit a day, and the file on disk is unchanged. Save (menu `Save` or Ctrl+S, as `react/save.spec.js` does) → the change is on disk.
4. **Invalid time**: type `"25:99"` + Enter → `aria-invalid`, blur reverts, and the file is unchanged.
5. **View in table editor**: the button on a game opens a new active "SeasonGame" tab with the game's row selected (reuse `TableEditorPage` / `Grid` helpers from the React models). Back on Schedule, the right-click menu does the same.
6. **Default editor**: `preferences: { general: { defaultEditor: "open-schedule" } }` → opening the file lands on Schedule.
7. **Re-read on mount**: edit a game's DayOfWeek in the table editor (SeasonGame tab), then go back to Schedule → the row shows the new day.
- Tag `@slow` on any test that takes ≥ 15 s (likely only 2/3 if polling the disk is slow).
- This spec counts as the React port of `bulk-edit.spec.js`'s "schedule editor changes are saved to the file". Leave the v4 spec unchanged. Mark that item done under 04e in `04-parity.md`.
